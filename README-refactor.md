# NextObsession: розділення файлів

Цей архів оновлює наявний проект. Він не замінює package.json, Wrangler-конфіг,
міграції або локальну базу.

## Встановлення

1. Зупини локальний сервер через Ctrl+C.
2. Зроби резервну копію папки проекту.
3. Скопіюй папки src та public з архіву в корінь проекту зі злиттям папок
   і заміною наявного src/index.js. Не видаляй інші свої файли з src.
4. У свій наявний wrangler.jsonc або wrangler.json додай на верхньому рівні:

```json
"assets": {
  "directory": "./public",
  "binding": "ASSETS",
  "run_worker_first": false
}
```

Між сусідніми властивостями JSON потрібна кома. Наприклад, після масиву
"d1_databases": [...] постав кому перед новою властивістю "assets".
Якщо assets вже існує, онови його замість створення другого однойменного блоку.
Збережи name, main, routes, d1_databases, previews та решту свого конфігу.
Значення main має залишитися src/index.js. Приклад у wrangler.assets.example.jsonc
є тільки фрагментом, ним не можна замінювати весь поточний конфіг.

Якщо ти використовуєш wrangler.toml, еквівалентний блок:

```toml
[assets]
directory = "./public"
binding = "ASSETS"
run_worker_first = false
```

5. Запусти:

```powershell
npm run dev
```

6. Відкрий http://127.0.0.1:8787 і перевір головну, сортування, підвантаження,
   профіль, галерею та зум. Додатково відкрий /assets/css/site.css:
   має з'явитися текст CSS, а не помилка чи HTML-сторінка.

Для GitHub потрібно додати всі нові файли src і public та змінений Wrangler-конфіг.
Один src/index.js більше не містить увесь сайт. Wrangler розгортає модулі та
статичні файли разом. Окремої build-команди для цього рефакторингу не потрібно.

## Файли

| Файл / папка | Призначення |
| --- | --- |
| src/index.js | Маршрути та обробка помилок |
| src/pages/home.js | Головна сторінка |
| src/pages/creator.js | Сторінка креатора |
| src/pages/errors.js | Сторінки помилок |
| src/components/layout.js | Спільний HTML, шапка, футер, CSS/JS-підключення |
| src/components/creator.js | Картка, статистика, ціна, кнопки та зображення |
| src/components/lightbox.js | HTML модалки |
| src/services/directory.js | Запити D1, сортування, випадковий порядок та курсори |
| src/routes/api.js | API каталогу і перевірка бази |
| src/lib/html.js | Екранування HTML, URL та форматування |
| src/lib/responses.js | HTTP-відповіді та захисні заголовки |
| public/assets/css/site.css | Базові стилі |
| public/assets/css/creators.css | Картки, ціни та розміщення елементів профілю |
| public/assets/css/lightbox.css | Галерея та зум |
| public/assets/css/directory.css | Сортування та підвантаження |
| public/assets/js/lightbox.js | Зум, перетягування та перемикання зображень |
| public/assets/js/directory.js | Нескінченне завантаження та зміна сортування |
| public/_headers | Заголовки статичних файлів |

## Перевірка

Пройшли автоматичні перевірки всіх 11 порядків сортування на SQLite, пошуку,
курсора, цін, HTML-екранування, помилок, підвантаження та зуму. Окремо перевірено,
що кожен CSS/JS-файл з HTML існує, JS має коректний синтаксис, а статичні запити
передаються до ASSETS без звернення до D1. Перевірка ASSETS зроблена з тестовою
реалізацією binding. Wrangler dev/deploy та візуальний тест у браузері в цьому
середовищі не запускалися.

Схема D1 та функції сайту збережені. Рефакторинг не усуває попереднє обмеження
масштабування випадкового SQL-порядку; його оптимізуємо окремо перед зростанням
до сотень тисяч записів.

Документація: https://developers.cloudflare.com/workers/static-assets/binding/
