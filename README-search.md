# NextObsession: пошук та локація

Це оновлення для вже розділеної версії сайту. Архів містить тільки змінені
та нові файли. Збережи резервну копію проекту, потім скопіюй вміст архіву
в корінь проекту зі злиттям папок і заміною відповідних файлів.

## Одноразова міграція

Потрібно створити пошуковий індекс у тій базі, яку використовує Worker.
Команди нижче припускають database_name = nextobsession-db у твоєму Wrangler.
Якщо він відрізняється, використай своє значення database_name.

Зупини npm run dev через Ctrl+C. Для локальної бази виконай:

```powershell
npx wrangler d1 execute nextobsession-db --local --file=./migrations/20261117_creator_search.sql
npm run build
npm run dev
```

Перед публікацією коду застосуй той самий SQL-файл до відповідної віддаленої
бази. Для неї команда використовує --remote замість --local:

```powershell
npx wrangler d1 execute nextobsession-db --remote --file=./migrations/20261117_creator_search.sql
```

Якщо dev та main мають різні D1-бази або Wrangler env, застосовуй міграцію
окремо для кожної потрібної бази, використовуючи її конфіг та ім'я.
Міграція не змінює записи creator: вона створює FTS5-індекс, тригери його
оновлення та індексує наявні записи. Повторний запуск дозволений і перебудує
індекс. Резервна копія перед змінами бази рекомендована.
Без міграції головна без запиту працює, але новий пошук не працюватиме.

Після встановлення повністю онови сторінку. Формат курсора змінився, тому
старі відкриті порції каталогу треба почати знову з головної сторінки.

## Пошук

- Пошук виконується в SQL за name, username, location, bio та website.
- Шукає всередині рядків, а не лише на початку.
- Всі слова запиту мають бути присутні. Допускаються частини слів,
  інший порядок слів і збіги різних слів у різних полях.
- Першими йдуть збіги в імені, потім username, location, bio, website.
- У межах поля: точний збіг, початок із цілим словом, окреме слово/фраза,
  частина рядка, потім набір усіх слів в іншому порядку.
- Для rose: Rose, Rose Marie, Emma Rose, Roselyn, потім username/location/bio.
  Початок слова Roselyn вважається частковим збігом за наведеним прикладом.
- Якщо всі слова знаходяться тільки в сукупності різних полів, такий
  профіль теж знаходиться, але після збігів усіх слів в одному полі.
- Релевантність розраховується до LIMIT та враховується у курсорі.
- При пошуку перший пункт сортування називається Relevance, а однакові
  оцінки розв'язуються за username. Інші сортування застосовуються всередині
  однакової оцінки релевантності. Без запиту збережено Random.
- Запити регістронезалежні; перевірено ASCII, кирилицю та латиницю з акцентами.
  Використано Unicode-aware триграми та додаткову нормалізацію символів запиту.
- Символи %, _ та лапки є звичайним текстом, а не операторами пошуку.
- Текстові website включено; URL аватара/банера, службові дати, статуси
  та числові лічильники не трактуються як зміст профілю.

Триграми прискорюють відбір кандидатів для слів від 3 символів. Запити,
що складаються лише з 1-2-символьних слів, працюють через сканування.
Широкі популярні запити також можуть повертати багато кандидатів: їхню
вартість і час треба вимірювати на реальному D1 перед великими обсягами.
Міграція використовує тригери для синхронізації після INSERT/UPDATE/DELETE;
після звичайного імпорту профілів вручну перебудовувати індекс не потрібно.

## Локація

Перед непорожньою локацією показується SVG-іконка 14 px у поточному кольорі.
Зміна застосована на профілі та картці. Порожня/пробільна локація не створює
ані іконки, ані контейнера. Висота карток залишається однаковою.

## Змінені файли

- src/services/search.js: новий модуль пошуку та SQL-релевантності.
- src/services/directory.js: інтеграція пошуку і курсор релевантності.
- src/components/creator.js: компонент локації.
- src/pages/creator.js: локація на профілі.
- src/pages/home.js: назви, підказки та режим Relevance.
- src/components/layout.js: нова версія CSS для оновлення кешу.
- public/assets/css/creators.css: іконка і вирівнювання карток.
- migrations/20261117_creator_search.sql: індекс і тригери.

## Перевірки

Пройшли SQLite-тести часткових збігів, порядку полів і якості збігу,
регістру, багатослівних запитів, спецсимволів, змін індексу та повторної
міграції. Перевірено план запиту: кандидатів відбирає FTS MATCH-індекс.
На 155 відповідних записах перевірено повний обхід усіх порцій без повторів
і втрат для всіх 11 варіантів сортування, зі збереженням релевантності.
Перевірено відсутність порожньої локації в HTML картки та профілю.
Повторно пройшли тести попередніх сортувань, цін, пошуку і помилок.
Запуск міграції на твоєму D1 та візуальна перевірка виконуються у тебе.
